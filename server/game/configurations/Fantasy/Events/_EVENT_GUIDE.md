# События (YAML)

`.yaml`-файл в этой папке описывает одно или несколько событий. Файлы,
начинающиеся с `_` (например `_settings.yaml`), событиями не считаются.

Каждый месяц с шансом `EVENT_SETTINGS.bunker_event_chance` движок выбирает одно
подходящее событие: проверяет `when`, набирает `participants` и взвешивает по `weight`.

## Несколько событий в одном файле

Чтобы держать связанные события вместе (например событие и его follow-up из
`schedule`), в одном файле можно объявить сразу несколько. Подойдёт либо список
верхнего уровня, либо ключ `events:`:

```yaml
events:
  - id: rats_arrive
    type: flavor
    title: Гости
    text: ...
    schedule:
      - { event: rats_spread, in: 1 }
  - id: rats_spread
    type: flavor
    scheduled_only: true
    title: Расплодились
    text: ...
```

`id` каждого события по-прежнему должен быть уникален среди всех событий пака.

## Альтернативный текст и переменные

Чтобы события меньше повторялись, прямо в любом тексте (title, text, описаниях
исходов) можно использовать:

- **Инлайн-альтернативы** `{крыс|мышей|тараканов}` — движок подставит один
  случайный вариант.
- **Переменные события** `{event.animals}` — объявляются в блоке `vars` и
  выбираются один раз на показ (одно и то же имя в title и text совпадёт):

  ```yaml
  vars:
    animals: [крыс, мышей, тараканов]   # список — случайный элемент
    place: "тёмном {углу|коридоре}"     # строка (можно с альтернативами)
  text: Несколько {event.animals} пробрались в убежище и засели в {event.place}.
  ```

- **Поля события** `{event.id}`, `{event.type}`, `{event.title}`, `{event.weight}`.

## Поля события

```yaml
id: unique_id            # обязательно, уникально среди всех событий
type: flavor | choice    # flavor — текст + эффекты; choice — варианты с голосованием
weight: 2                # относительная частота (по умолчанию 1)
scheduled_only: true     # появляется только как follow-up из schedule
when:                    # условия появления (все И)
  min_month: 2
  max_month: 10
  min_players: 2
  max_players: 8
  flag_set: [some_flag]
  flag_unset: [other_flag]
participants:            # роли подбираются из активных игроков (всегда разные люди)
  victim: {}                              # любой активный
  man: { gender: Мужчина, min_age: 18 }   # фильтры: gender, profession, min_age, max_age
title: Заголовок
text: Текст с плейсхолдерами {victim}, {man.profession}, {participants}
effects: [ ... ]         # для flavor
options: [ ... ]         # для choice
schedule: [ ... ]        # отложенные follow-up события
select: { kind: player, prompt: "..." }   # для choice: показать выбор цели (роль chosen) или предмета
```

Если какую-то роль из `participants` нельзя заполнить — событие пропускается.

### Выбор ресурсов (`select`)

`select` показывает пикеры в choice-событии. `kind` — один вид, либо `kinds` —
несколько сразу:

```yaml
select:
  kind: item                       # один пикер
  prompt_item: Посмотрите, что есть на складе
```

```yaml
select:
  kinds: [item, profession]        # сразу предмет и профессия
  prompt_item: Посмотрите, что есть на складе
  prompt_profession: Кто возьмётся за дело
```

Виды: `player` (цель, доступна эффектам как роль `chosen`), `item` (предметы из
рюкзаков, инвентаря и бункера — те же, что в событии «еда закончилась»),
`profession` (профессия одного из выживших). Предметы расходуются, если у
варианта стоит `consume_items: true`.

### Исход по выбору (`outcomes_by_selection`)

Когда вариант зависит от того, сколько ресурсов выбрали (например «и предмет, и
профессия»), используйте `outcomes_by_selection` вместо `effects`/`outcomes`.
Движок считает, сколько запрошенных видов-ресурсов (`item`/`profession`) выбрано:

- `all` — выбраны все запрошенные виды;
- `some` — выбрана только часть (например, предмет, но без профессии);
- `none` — не выбрано ничего.

Каждый ключ — массив исходов в формате `outcomes` (исход без `chance` — остаток),
так что «50% на 50%» при частичном выборе пишется внутри `some`:

```yaml
select:
  kinds: [item, profession]
options:
  - id: repair
    label: Взяться за дело
    consume_items: true
    outcomes_by_selection:
      all:
        - { text: "Всё получилось.", effects: [{ on: all, sanity: 6 }] }
      some:
        - { chance: 50, text: "Кое-как удалось.", effects: [{ on: all, sanity: 3 }] }
        - { text: "Не вышло.", effects: [{ on: all, health: -8 }] }
      none:
        - { text: "Наугад — стало хуже.", effects: [{ on: all, health: -12 }] }
```

### Индикатор шансов

Для вариантов с `outcomes` или `outcomes_by_selection` клиент сам показывает
полоску шансов под вариантом: доля каждого исхода по `chance` (исход без
`chance` — остаток до 100%). Цвет берётся из суммарного знака эффектов исхода
(здоровье + рассудок + значение статуса + еда; `kill` — сильный минус):
плюс — зелёный («удача»), минус — красный («риск»), ноль — серый. Для
`outcomes_by_selection` полоска пересчитывается вживую по тому, сколько
ресурсов (`item`/`profession`) уже выбрано (`none`/`some`/`all`), так что игроки
видят, как выбор улучшает шансы. У вариантов с детерминированными `effects`
полоски нет.

**Качество профессии.** Шанс успеха зависит не только от числа выбранных
ресурсов, но и от уровня навыка выбранной профессии: каждый предмет весит 1, а
профессия — по множителю своего уровня `SKILL_LEVELS`. Множитель задаётся в
конфиге пака третьим параметром: `[Начинающий, 0.4, 0.6]` (вес 0.4 — частота
выпадения, 0.6 — вклад в шанс; по умолчанию 1). Сумма весов × 40% даёт шанс
(потолок 90%, либо 100% при полном наборе всех заявленных видов). Так эксперт
(множитель 1.5) поднимает шансы заметно сильнее новичка (0.6).

## Эффекты

Цель задаётся в `on`: имя роли, `chosen` (из `select`), `all`, `others`
(все, кроме участников), `random`.

```yaml
- { on: victim, health: -16 }
- { on: victim, sanity: 4 }
- { on: victim, status: { id: infection, label: Воспаление, stat: health, value: -6, months: 2 } }
- { on: victim, clear_status: infection }   # или clear_status: debuffs
- { food: 180 }                             # положительное число — добавить
- { food: "10%" }                           # строка "N%" — потерять процент запаса
- { flag: { some_flag: true } }
- { on: chosen, kill: true }
- { kill_random: true }                     # случайный, кроме участников
- { add_room: true }
- { on: mother, spawn_survivor: true }      # новый житель без «взрослых» атрибутов
```

В одном объекте можно совмещать операции: `{ on: victim, health: -5, sanity: -5 }`.

### Новый выживший (`spawn_survivor`)

`spawn_survivor` добавляет в бункер нового жителя без взрослых атрибутов
(возраст 0, нет профессии/хобби/фобии/тела/инвентаря — только раса, пол и
здоровье). Если задан `on`, новорождённый наследует расу указанного родителя.
Имя берётся из встроенного пула либо `{ spawn_survivor: { name: "Имя" } }`.
Появление показывается в итогах события (`players_added`).

### Последствие по истечении статуса (`on_expire`)

У статуса может быть `on_expire: { event: <id>, carry_as: <роль> }` — когда
дебафф/бафф истекает (через `months`), движок запускает указанное событие, а его
носитель приходит туда под ролью `carry_as` (по умолчанию `self`). Так
моделируются отложенные последствия: беременность → роды, болезнь → осложнение.

```yaml
- { on: woman, status: { id: pregnancy, label: Беременность, stat: sanity,
    value: -5, months: 9, on_expire: { event: childbirth, carry_as: mother } } }
```

## Варианты (choice)

Игроки голосуют за вариант; победитель применяет свои эффекты. Вариант — либо
детерминированные `effects`, либо взвешенные `outcomes` (исход без `chance` —
остаток вероятности).

```yaml
options:
  - id: medicate
    label: Потратить лекарство
    consume_items: true        # израсходовать выбранные в пикере предметы
    effects:
      - { on: patient, health: 16, clear_status: debuffs }
  - id: wait
    label: Переждать
    outcomes:
      - chance: 40
        text: Жар отступил сам собой.
        effects: [{ on: patient, health: 4 }]
      - text: Стало хуже.
        effects: [{ on: patient, health: -16 }]
```

### Пикер для конкретного варианта (`requires`)

Пикеры из `select` показываются не сразу: они появляются у игрока **только после
того, как он проголосует за вариант**, которому нужен выбор. Какие именно пикеры
открывает вариант, задаёт его `requires` (`player`/`item`/`profession`). Варианты
без `requires` пикеров не показывают.

`select` по-прежнему задаёт подписи пикеров (`prompt`/`prompt_item`/
`prompt_profession`) и виды ресурсов для `outcomes_by_selection`.

```yaml
select:
  kind: player
  prompt: Кого отправить?
options:
  - id: send
    label: Отправить добровольца
    requires: [player]            # пикер человека откроется после выбора варианта
    outcomes: [ ... ]
  - id: seal_off
    label: Запечатать отсек       # пикеров нет
    effects: [ ... ]
```

## Цепочки (schedule)

`carry` проносит роли в follow-up; там они доступны как обычные роли.

```yaml
schedule:
  - { event: morning_rumors, in: 1, carry: [man, woman] }
```

Целевое событие обычно помечают `scheduled_only: true`, чтобы оно не выпадало само.
